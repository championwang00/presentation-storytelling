# 视觉提案与演示讲述

把演示稿做成一条观众能跟上的论证。每页决定观众此刻要看见什么，讲稿补上为什么，以及这一页如何引到下一页。

## 从现有材料搭叙事

- 先看用户已有的草稿、参考、反馈和实际使用场景。记录已确定的判断、待验证的假设和素材状态。编辑现有稿时，按页标题和内容定位，避免插页之后改错对象。
- 比较方向时，早期或次要方案可以用一个标题、一句主张和一页参考带过。说清它解决了什么、留下什么问题，以及哪个优点值得带到下一案。若两个顾虑一起催生推荐方向，先把它们合成观众能复述的问题，再翻页给出推荐。
- 推荐概念首次出现时，用一句话说清它代表什么。名称、定位或风格有多个组成部分时，可以用分叉图解释。不同子方向需要各自的参考或说明时，先用过渡交代它们的共同出发点，再各用一页讲清。
- 有视觉参考时，先让观众看一张或一组关键画面，再指出具体细节如何产生所说的感受。有足够素材且需要证明适用范围时，再用拼贴比较跨媒介应用。注明出处，并区分原案例、现有素材和新尝试。
- 把推荐方向落到真实任务。挑有差异的题材、受众或触点并排对照，讲清哪些元素共用、哪些随内容变化、哪些小尺寸下仍难辨认。已有品牌、角色或界面与决策相关时，也用一两个实际触点检验。尊重用户指定的素材生成分工，复用已提供的图。
- 收尾可以把关键感受或成功标准汇到推荐概念，再用具体文案说明它如何延伸到产品、品牌或后续传播。用本次任务的判断标准组织内容。页数、方案数量和顺序随材料调整。

## 一页怎么做

| 层次 | 放什么 |
| --- | --- |
| 第一眼 | 主标题、关键图，或一个能接住上下页的问题 |
| 看得懂 | 少量标签、对照项或分支。用尺寸、颜色、位置体现主次 |
| 讲得清 | 讲稿解释观察、因果和过渡，用适合讲述者的口语 |

分叉图里，把要拆解的词放在最强一层。对应关系用较小文字，原定义需要带回时放在更弱的第三层。用细线辅助读序。有辨识作用时才用 emoji，字号随标题或标签，按实际投影尺寸检查。

逐步揭示只用于有先后关系的内容。第一屏让观众先看到能独立理解的画面，后续步骤与讲稿段落对齐。全页参考或横向对照需要一起看时，同时呈现。

## 交付和验收

- 按用户指定的格式交付。需要可编辑稿时，标题、正文和结构保留为可编辑对象，参考图放在独立对象里。将演示稿、讲稿和可选配音预览视为不同交付层。
- 先按目标场合走读一遍，确认上一页的问题在后面被接住，推荐方向有应用证据，讲稿与画面、页码和目录一致。插页或改文案后，从相邻页再走一次。
- 有逐步展示、配音或离线媒体需求时，读 [演示播放验收](references/playback.md)。讲稿在迭代时先保留可编辑文本，定稿后再生成正式配音。
- 将作品上传到用户指定的平台时，检查上传后的页面、媒体和版本。公开发布前核对实际发布的文件和历史，排除凭证、内部链接、私有素材和聊天记录。
